LOCAL PATCHES
-------------
worker/index.mjs, /stream — two `.catch(() => {})` guards, both marked PATCHED
  in the source.

  `send()` is called un-awaited from the `onProgress` and `onNote` callbacks,
  and `writer.close()` runs in a `finally` inside an async function nothing
  awaits. When a browser closes the EventSource mid-crawl, every remaining
  write rejects with ResponseAborted and the close rejects with "Invalid
  state: WritableStream is closed" — as unhandled rejections, which under Node
  can take the process down. Cloudflare hides this because `ctx.waitUntil`
  owns the promise there; we pass `ctx` as null, so they surface.

  Worth sending upstream — it is a bug in any local adapter, not just here.

src/http.mjs — `guardFetches()`, a hook every Fetcher.get asks before it
  fetches, marked PATCHED.

  A hosted crawler fetches whatever a form, sitemap or link names, so without
  it a page listing http://169.254.169.254/ reads the server's cloud metadata
  into a report. The rule needs DNS, which differs between Node and Workers,
  so the engine only asks; lib/ssrf.ts answers. Unset, nothing changes —
  upstream behaviour is untouched.

src/console.mjs:484 — two `/*turbopackIgnore: true*/` comments.

  `dotfile` is ~/.config/seo-audit/.env, outside the project by design, so
  Turbopack's static analysis gives up and traces the entire repository into
  the server bundle. Ours only, not upstream's problem: a bundler comment in a
  file the CLI runs unbundled.

REMOVED LAYERS
--------------
The front ends and the internal server are gone: mac/ (the SwiftUI app),
desktop/ (the Tauri shell), raycast/ (the extension), Casks/, Package.swift,
src/serve.mjs (`--serve`, the node:http adapter around the worker) and their
workflows, scripts and tests. Next.js is the only front end here, and
lib/engine.ts is the only adapter — it calls worker/index.mjs directly for
preview, stream and render, which is why worker/ stays.

A diff against upstream will show all of it as deleted. That is deliberate,
not drift.
